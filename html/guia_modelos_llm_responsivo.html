Visão geral

O que é um LLM?

Um LLM é um modelo de IA treinado em grandes volumes de texto e outros dados para estimar e gerar sequências de tokens. Na prática, ele pode responder perguntas, resumir, traduzir, programar, extrair informações e agir sobre ferramentas.

Dados→Tokens→Transformer→Probabilidades→Resposta
Ideia central: o LLM não “consulta uma verdade” por padrão. Para conhecimento externo e atualizado, use RAG, ferramentas ou busca.
ContextoO que o modelo recebe agora.
PesosO conhecimento aprendido.
FerramentasAPIs, bancos, navegador, código.
AvaliaçãoQualidade, segurança, custo e latência.

1. Gerenciamento de Contexto e Prompting

🧠 Contexto: como orientar o comportamento

Instruções

Definem objetivo, restrições, critérios e formato.

Exemplo: “Explique recursão para alunos do 1º período, em até 250 palavras, com exemplo Python.”

System prompt

Você é um tutor de Ciência da Computação.
Priorize precisão, exemplos executáveis e linguagem didática.
Quando houver incerteza, sinalize-a.

Zero-shot, one-shot e few-shot

  • Zero-shot: só instrução.
  • One-shot: um exemplo.
  • Few-shot: vários exemplos.

Memória

Curta, persistente ou recuperada de base externa.

Cuidado: aplique consentimento, minimização e retenção adequada.

Otimização de tokens

  • Resumir histórico antigo.
  • Remover duplicação.
  • Selecionar apenas documentos relevantes.

Saída estruturada

{
  "classificacao": "positivo",
  "confianca": 0.92,
  "justificativa": "..."
}

🧩 Bons prompts

  1. Contexto
  2. Tarefa
  3. Restrições
  4. Critérios
  5. Formato
  6. Exemplos
Template: “Atue como [papel]. Dado [contexto], execute [tarefa]. Respeite [restrições]. Produza [formato].”
Antipadrão: prompts vagos produzem respostas genéricas.

2. Dados Externos, RAG e Engenharia de Conhecimento

📚 Pipeline RAG

1
Ingestão

PDF, HTML, DOCX, APIs.

2
Extração

Texto, tabelas, metadados.

3
Chunking

Trechos com contexto.

4
Embeddings

Vetores semânticos.

5
Busca

Top-k + filtros + reranking.

6
Geração

Resposta baseada nas fontes.

Exemplo: um assistente acadêmico busca no regulamento os trechos sobre aproveitamento de créditos e responde com base neles.

✂️ Chunking

  • Fixo: 300–800 tokens.
  • Semântico: títulos e parágrafos.
  • Hierárquico: resumo + detalhes.
  • Por entidade: normas e contratos.
Trade-off: chunks pequenos perdem contexto; grandes aumentam custo.

🔎 Retrieval + reranking

  • Busca semântica.
  • Busca lexical/BM25.
  • Filtros por metadados.
  • Reranking dos candidatos.
Busca híbrida: muito útil em código, normas e textos com siglas ou identificadores exatos.

🧪 Exemplo conceitual em Python

pergunta = "Qual a política de estágio?"
chunks = buscar_documentos(pergunta, top_k=5)
contexto = "\n\n".join(chunks)

prompt = f"""
Responda somente com base no contexto.
Se não houver evidência, diga que não encontrou.

CONTEXTO:
{contexto}

PERGUNTA:
{pergunta}
"""

resposta = llm(prompt)

3. Modelos Open Weight e Proprietários

🔓 Open Weight

  • Controle de infraestrutura e dados.
  • Quantização e ajuste local.
  • Bom para pesquisa e cenários on-premise.
  • Exige serving, segurança e observabilidade.

Exemplos de famílias: Llama, Mistral/Mixtral, Qwen, Gemma e Phi.

Importante: open weight não significa automaticamente open source. Verifique a licença.

🔒 Proprietários / via API

  • Menor esforço de infraestrutura.
  • Escala gerenciada.
  • Recursos multimodais e ferramentas.
  • Dependência de preço, limites e políticas do provedor.

Fornecedores: OpenAI, Google, Anthropic, Cohere e outros.

CritérioOpen Weight / LocalProprietário / API
DadosMaior controleDepende do contrato
InfraestruturaResponsabilidade da equipeGerenciada pelo provedor
CustomizaçãoAltaVariável
CustoHardware + operaçãoNormalmente por uso/tokens
EscalaPrecisa ser projetadaMais simples para o cliente

4. Ajuste e Treinamento

🎯 Fine-tuning

Adapta o comportamento a tarefas, estilo e formatos específicos.

Não use como banco de dados: para fatos mutáveis, prefira RAG.

⚙️ PEFT / LoRA

Ajusta pequena parcela dos parâmetros, reduzindo memória e custo.

Bom para: domínio, estilo ou tarefa bem definidos.

👍 RLHF / DPO

Usam preferências humanas para alinhar o comportamento do modelo.

Exemplo: avaliadores escolhem entre respostas A e B e o modelo aprende a favorecer a melhor.

🔌 MCP e ferramentas

Protocolos e interfaces padronizadas podem expor ferramentas e recursos ao modelo.

Risco: agentes têm poder de ação. Use menor privilégio, confirmação e auditoria.

🧰 Agentic harnesses

Camada de execução que envolve o LLM com prompts, ferramentas, memória, políticas, retries, tracing e controles.

8. Implantação Local e On-Premise

🖥️ Componentes

Hardware

GPU, VRAM, RAM, CPU e armazenamento.

Inferência

vLLM, TGI, llama.cpp, Ollama.

Quantização

FP16/BF16, INT8, 4-bit, GGUF.

API

Auth, rate limit, streaming, logs e métricas.

💻 Exemplo com Ollama

ollama pull llama3.2

ollama run llama3.2 \
  "Explique embeddings para um aluno de graduação."

📐 Memória: aproximação

FP16 ≈ 2 bytes/parâmetroINT8 ≈ 1 byte/parâmetro4-bit ≈ 0,5 byte/parâmetro
Memória real é maior: KV cache, buffers, runtime, contexto e batching também consomem VRAM/RAM.

12. Boas Práticas, Segurança e Governança

🛡️ Segurança

  • Proteja secrets.
  • Aplique autenticação e autorização.
  • Defenda contra prompt injection.
  • Use sandbox para código.
  • Confirme ações irreversíveis.

⚖️ Governança e LGPD

  • Finalidade e base legal.
  • Minimização de PII.
  • Versionamento de modelos e prompts.
  • Auditoria de riscos e vieses.
  • Revisão humana em decisões de alto impacto.
